# LeaveFlow для Авистрейд

Клиентский прототип сбора пожеланий и согласования предварительного плана отпусков. Сотрудник предлагает даты, видит ограничения и свои периоды; HR рассматривает пожелания, согласует корпоративные исключения и управляет тремя параметрами регламента.

## Запуск

Нужен Node.js не ниже 22.12.0. Проверено на Node.js 24.11.0 и npm 11.6.1 в Windows.

```sh
npm ci
npm run dev
```

Открыть http://localhost:3000. API-ключи, Gemini и файл `.env` не нужны. Зависимости зафиксированы в `package-lock.json`. Для первого скачивания пакетов требуется интернет; внешние веб-шрифты имеют системный fallback.

```sh
npm test
npm run lint
npm run build
npm run preview
```

`npm test` запускает 7 исходных проверок правил и 84 теста регрессии, HR-аналитики, остатков, неоплачиваемых отпусков и полного демонстрационного набора. `build` сначала проверяет типы, затем создаёт статическую сборку в `dist`. Подробности проверки и найденных ошибок — в [REVIEW.md](REVIEW.md).

## Два дополнительных инструмента HR

HR → **Контроль плана** → **Сбор пожеланий** показывает весь активный штат выбранного отдела и периода, включая тех, кто ничего не отправил. Отдельно видны ожидание сотрудника, корректировка и ожидание решения HR. Можно подготовить и скопировать адресный список для напоминания; сообщения автоматически не отправляются. Личные черновики не раскрываются.

HR → **Контроль плана** → **Замещающие** показывает пересечения, когда на одного человека назначено несколько отсутствующих. Согласованные назначения отделены от потенциальных пересечений ожидающих пожеланий. Сигнал также показывается при рассмотрении пожелания и сам по себе не создаёт нового запрета компании.

Исследование, ограничения и короткий сценарий демонстрации — в [HR_FEATURES.md](HR_FEATURES.md). Для подготовленного примера нужно сбросить демо: Иван Морозов указан замещающим в двух пожеланиях на 9–15 августа 2027 года. Существующее локальное состояние автоматически не сбрасывается.

## Сценарий сотрудника

1. На главной странице видны согласованные дни, ожидающие пожелания, летний расход и список отпусков за весь год. Переключение календаря между полугодиями не скрывает личные карточки другого полугодия.
2. Нажать «Запланировать отпуск» либо выбрать первый и последний день прямо в календаре. Форма изначально закрыта и не содержит фиктивно выбранных дат или автоматически назначенного замещающего.
3. Выбрать замещающего, при желании добавить комментарий. Корпоративные ограничения не запрещают предложить даты, но требуют отдельного checkbox подтверждения.
4. Отправить пожелание или сохранить черновик. Черновик можно продолжить, возвращённое пожелание — исправить с сохранением ID. Отзыв отправленного пожелания требует подтверждения и переносит запись в «Историю».
5. Карточка показывает решение HR, причину возврата/отказа и собственную историю действий. Правовые коды и справочники не вынесены в основной экран сотрудника.

| Вид                            | Обозначение                                                     |

| Свободные даты                 | Белые, с текстом «Свободно»                                     |
| Ограничение по занятости       | Розовая штриховка, подпись «Ограничение»; даты можно предложить |
| Мой согласованный отпуск       | Тёмно-зелёный, галочка и подпись «Мой отпуск»                   |

## Демонстрация за три минуты

Демо-настройки спрятаны в верхней панели. Это инструменты показа, не реальные права доступа. Смена роли на HR сохраняет выбранного сотрудника для обратного переключения.

1. Начать после сброса, сотрудник Иван Морозов. В календаре августа выбрать 23–29 августа, замещающим — Ольгу Васильеву. Есть конфликт: два МПП уже отсутствуют. Проверить, что отправка требует отдельного подтверждения.
2. Отправить; в «Демо-настройках» выбрать роль HR. В «Очереди пожеланий» открыть только что созданную запись Ивана.
3. «Согласовать исключение»: основание изначально пустое; ввести не менее 10 символов и подтвердить. Правовой/конфигурационный запрет нельзя обойти этой кнопкой.
4. Вернуться к роли сотрудника. Период зелёный, карточка содержит решение. Перезагрузить страницу: решение остаётся.
5. HR → «Корпоративные правила» → лимит МПП 2 → 3, обязательное основание. Видны затронутые периоды, версия и журнал. Предыдущие решения не отменяются.
6. Открыть пожелание Дениса Васильева с примером 12+12. Обычное согласование и корпоративное исключение недоступны; доступны возврат и отказ.

Сброс: «Демо-настройки» → «Сбросить демо» → подтверждение. Восстанавливает seed, пользователя Ивана, август и II полугодие. Остальные ключи браузера не удаляются.

## Реализованные правила

- Лимит уникальных МПП считается по каждому дню; два раздельных пересечения не означают трёх одновременно.
- Матрица несовместимости симметрична и задана явными парами демонстрационной оргструктуры.
- Согласованные исключения продолжают занимать ёмкость; ожидающие пожелания не резервируют её. Конкуренция проверяется по связанным должностям.
- Летний расход суммарный за 1 июня–31 августа конкретного года, без нерабочих праздников. Показывается согласованный расход с кандидатом и отдельно другие ожидающие дни.
- Срок в календарных месяцах считается от бизнес-даты отправки, не от фактической даты компьютера и не от даты согласования. День 31 ограничивается последним днём следующего месяца.
- Замещающий обязателен, активен и отличается от заявителя. Его подтверждённое отсутствие — корпоративный конфликт.
- Выбранные правовые проверки: праздники 2027 года, рабочий год и полнота истории, число частей и основание более двух, одна часть не менее 14 дней, демонстрационное право на дни, признак отдельной правовой проверки.
- Короткая часть не требует конфликтного checkbox только из-за напоминания о будущей части от 14 дней. Корпоративный конфликт, конкуренция и правовые препятствия требуют подтверждения.
- Команды проверяют автора, разрешённый переход, текущее состояние и полное подтверждение показанных ограничений. Исключение не обходит ошибки формы.

## Границы прототипа

Демо-дата фиксирована: **28.10.2026**, план — **2027 год**. Полный правовой движок, настоящая авторизация, сервер, синхронизация устройств/вкладок, официальные остатки, уведомления, перенос согласованного отпуска, выплаты и кадровые документы не реализованы. Рабочие годы и права на дни — вымышленные входные данные. Общий срок до 5 января и внутренние полугодовые сроки не оформляются автоматически.

Всё состояние доступно браузеру; скрытие деталей в личном интерфейсе не защищает их от DevTools. Хранилище — ключ `leaveflow-demo-v2` в `localStorage`, схема совместима с исходными данными 2.0.0. Повреждённая запись не перезаписывается автоматически; при отказе сохранения показывается предупреждение. Изменения в этом режиме могут оставаться только в памяти до подтверждённого сброса.

Корпоративные допущения исходного ТЗ, включая область МПП, летнюю сумму, исключение праздников из неё и оргструктуру, остаются явно ограниченными демонстрацией. Они требуют подтверждения компании перед production. Положительная проверка не является заключением о полном соответствии законодательству.

## Развитие

Первый этап — backend с БД, авторизация и транзакции, реальные кадровые рабочие годы/остатки, согласование руководителем, подтверждённые локальные основания и юридическое покрытие, уведомления, перенос/отмена и интеграции.

AI имеет смысл для извлечения проектов правил из документа с цитатами, преобразования свободного текста в черновик и ответов по регламенту. Итоговые решения и изменение правил остаются за уполномоченным человеком, проверки дат — детерминированными.

## Остатки, сроки и неоплачиваемые отпуска

Сотрудник видит остаток для планирования и подробный расчёт по рабочему году. В форме можно выбрать отпуск без сохранения зарплаты по личным обстоятельствам или в связи с учёбой; HR проверяет основание перед решением. Во вкладке HR «Остатки и сроки» — близкие сроки контрактов и рабочих годов, незапланированные дни и редактирование срока контракта с аудитом.

Подробная логика, ограничения кадрового остатка, правовые источники и сценарий показа — в [BALANCES_UNPAID.md](BALANCES_UNPAID.md). Новые поля совместимы с прежним сохранением; отсутствующий вид запроса считается трудовым. Для ранее сохранённых сотрудников срок контракта нужно внести через интерфейс HR или восстановить демо-набор.

## Полный набор для показа

Для актуальных примеров загрузите полный набор кнопкой в баннере обновления либо через «Демо-настройки» → «Сбросить демо» → подтверждение. Старое сохранение не заменяется без подтверждения. Во II полугодии подготовлены три вида рисков замещения; во вкладке сроков — четыре приоритетных сотрудника. Все статусы личного кабинета, основания неоплачиваемых решений и согласованное исключение уже заполнены.

[DEMO_GUIDE.md](DEMO_GUIDE.md) — актуальная карта примеров с именами, датами и маршрутом показа за три минуты. Числа из предыдущих отчётов относятся к старому набору.
