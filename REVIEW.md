# Проверка LeaveFlow по ТЗ и исправления

Дата: 28.10.2026. Исходная ревизия: `1feb972`. Основание: ТЗ 2.0 из `public/assets/aistudio/` и уточнение пользователя о простом личном кабинете и различимых состояниях календаря.

## Вывод

Исходная реализация содержит полезное ядро: дневной подсчёт лимита, праздники, летнюю сумму, проверки частей и интерфейс HR. Однако её нельзя было считать проверенной по всему ТЗ: установка конфликтовала по зависимостям, команды допускали неверные переходы, сохранение повреждённых данных было небезопасным, а календарь и личный кабинет вводили пользователя в заблуждение. Исправления выполнены в отдельной ветке.

## Валидация

- `npm ci` — успешно выполнен в отдельном чистом каталоге без готовых node_modules; затем в нём также прошли тесты и сборка.
- `npm run lint` — проверка TypeScript.
- `npm test` — 7 исходных проверок и 28 новых регрессионных тестов.
- `npm run build` — проверка типов и production-сборка.
- Реальный браузер, локальный Vite: создание конфликтного периода → checkbox → отправка → HR → пустое обязательное основание → исключение → сотрудник → reload.
- В браузере проверены возврат с объяснением, исправление той же записи, повторная подача и обычное согласование.
- В браузере проверены сохранение черновика, продолжение, отправка, отзыв с подтверждением, раскрытие истории событий и сброс с последующей перезагрузкой.
- В браузере проверены изменение лимита, отклонение недопустимого числового значения без падения и отсутствие действия корпоративного исключения для примера 12+12.
- Контраст белого текста на `#007A60` — около 5.31:1. Статусы отличаются также подписями, иконками, пунктиром и штриховкой. Визуально проверен основной экран в доступном браузерном viewport; полный аудит WCAG и всех устройств не заявляется.

## Что остаётся ограничением MVP

Backend, настоящая защита данных, многопользовательская работа, официальный кадровый остаток, реальный маршрут руководитель → HR, перенос/отмена согласованного отпуска и юридическая полнота не реализованы и не объявляются исправленными багами. Юридические правила проверены на соответствие принятому ТЗ; полноценная правовая экспертиза локальных актов не проводилась.

Доступность одиночного дня в календаре описывает занятость команды. Ограничения, зависящие от всего диапазона и годового плана, окончательно проверяются в форме. Они не могут быть достоверно представлены одним цветом до выбора периода.

Компания должна подтвердить исходные допущения ТЗ: область лимита МПП, оргструктуру, суммарный летний максимум и исключение праздников из этой корпоративной суммы. Для продолжения разработки прототипа новых обязательных вопросов нет.
